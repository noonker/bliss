#+TITLE: bliss TODO

* Direction
From a review of whether the package makes sense. The core does: run the exact Guix or
Nix shell, directory and environment elsewhere, with one interface for every target.
It is built wider than it has been proven.
** TODO Decide the main use
Sandboxing AI agents, or moving dev work to bigger machines. The first makes the items
below the product and lets Kubernetes wait. The second shrinks =ai= to almost nothing and
makes two-way file sync matter more. This sets the order of everything else here.
** TODO Run one real agent task end to end
Through podman, with a real task, then judge whether the result is useful. So far agents
have only had version checks and login failures; none has completed any work.
** TODO Replace =pull= with something reviewable
=pull= drops a full copy in =.bliss/pull/<name>=, and working out what changed is left to the
user. Return a diff or a git branch that can be reviewed and applied. For agents, the
result is the point. Decide what happens in a directory that is not a git repository.
** TODO Send only allowed environment variables by default
The whole environment travels unless excluded, so secrets reach every target. Send a safe
default set plus names the user allows. Less magical, but this tool also pushes to
registries. =bliss run -n= should still list the names. =here= is not affected.
** TODO Make =ai= thin
Most of the hard bugs came from it: binary patching, native libraries, the Hermes installer.
Those fixes can break with any upstream release. Agents already in the Guix or Nix shell
could use =bliss run=, leaving =ai= as a shortcut for the command and its flags.
** TODO Narrow what is supported
Five target types, two package managers and four agents is more than can be kept working.
- Mark Docker, Nix over ssh and Autolith as experimental in the README.
- Consider dropping Hermes unless it is actually used.
- Keep =here= and emacs-bliss; both are small and fit the idea.
** TODO Clean up pushed Kubernetes images
Every run bakes the source into a new image and leaves its tag in the registry. =bliss stop=
and =bliss gc= do not touch registries. Delete the tag on stop where the registry allows it.

* Build
** TODO Keep output and status without keeping the session
After the command, run.sh keeps an interactive shell open, because =logs= reads the live pane
and =status= checks the session first. So every finished workload holds a session, and its
=env.sh= (the whole environment, secrets included) stays until =stop=. Write the output to a
file in the workload directory, have =status= read =exit= even with no session, and =logs=
read the file; then a non-interactive =ai PROMPT= run need not keep a shell.
agent-shell-org-loops stops in-place workloads once it has the reply, as a stopgap.
** TODO =gc= on =here= leaves orphaned workload directories
=HereTarget.gc= only logs a message, and only =stop= removes =state_dir()/workloads/<id>=.
A session that dies without =stop= leaves its =env.sh= behind. Remove directories no
record refers to, honouring =--dry-run=. (Found by an agent run, 2026-11-06.)
** TODO Non-x86_64 hosts
Now fails early with a clear error. Agent URLs, the loader path and the Nix image
are still hardcoded to x86_64.
** TODO =bliss logs -f= on ssh targets
Prints a notice and shows the output so far. =tmux pipe-pane= could provide it.
** TODO =bliss gc= leaves =~/.bliss/lib= on ssh targets
Only symlinks, recreated on each run.
